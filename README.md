# Kronos-R-Preview

Kronos-R-Preview treats each A-share stock as one causal document. A
hierarchical BSQ tokenizer converts normalized OHLC features into coarse/fine
codes, and a GPT-style Transformer predicts the next hierarchical token.

This tree is the clean post-bug-fix experiment line. Historical checkpoints
and metrics must not be mixed with new runs.

## Correctness fixes that require a full rerun

- RoPE angles are generated in FP32 with autocast disabled. Position indices
  are never rounded to bf16 before `sin`/`cos`.
- The fine head is aligned across training and inference: target fine token
  `t` is conditioned on target coarse token `t` during training and predicted
  coarse token `t` during inference.
- Fine EOS/padding uses `-100`; fine code `0` is a valid trained code.

Run the encapsulated numerical preflight before every formal study:

```bash
python experiment_io.py --require-cuda
```

## Ubuntu environment

Use Python 3.10 or newer. Install the CUDA-enabled PyTorch wheel appropriate
for the server first, then the remaining packages:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
# Install the correct CUDA PyTorch wheel for the server here.
python -m pip install -r requirements.txt
python experiment_io.py --require-cuda
```

No Conda, Windows drive, or local Python path is hardcoded. Every child process
uses the interpreter that launched the experiment.

Put the stock CSV files in `dataset/`. Required columns are `date`, `close`,
`high`, `low`, `open`, and `volume`; `amount` and `symbol` are optional.

## Server output layout

Large server-only artifacts and downloadable analysis artifacts are always
separated:

```text
server_runs/
├── weights/                    do not download
│   └── <experiment>/seed42/
│       ├── configs|arms|trials/  *.pt and *.ckpt
│       └── shared/               token/prepared-input caches
└── results/                    download this side
    └── <experiment>/seed42/
        ├── study_manifest.json
        ├── download_manifest.json
        ├── configs|arms|trials/
        ├── combined_epoch_summary.{json,csv}
        ├── analysis/proposal files
        └── plots and logs
```

On Ubuntu, moving both trees outside the repository is recommended:

```bash
export KRONOS_WEIGHTS_ROOT=/mnt/fast/kronos-weights
export KRONOS_RESULTS_ROOT="$HOME/kronos-results"
```

These variables are base directories; each runner adds its experiment and
`seed42` subdirectories. Equivalent full study paths can be supplied with
`--weights_root` and `--results_root`.

Only download the matching directory below `KRONOS_RESULTS_ROOT`. It contains:

- complete settings, command, source hashes, Git state, package/CUDA/GPU
  metadata, and dataset fingerprint;
- tokenizer per-epoch history, reconstruction metrics, top codes, and exact
  coarse/fine/joint count vectors;
- GPT per-epoch coarse/fine/regression losses, learning rates, update counts,
  sequence counts, timing, microbatch size, padding efficiency, and peak CUDA
  allocated/reserved memory;
- exact train/validation target coarse/fine/joint distributions;
- every checkpoint's full-coverage multi-window aggregate and per-date metrics;
- exact true/predicted coarse/fine/joint count vectors per window;
- a compressed record for every evaluated stock/date prediction, sufficient
  to reconstruct per-stock/per-date distributions and confusion matrices;
- logs, plots, CSV summaries, and a SHA-256 download manifest.

No model state or reusable cache is written under the results root.

## Iterative experiment workflow

Run one formal stage, download its results directory, and review it before
recording the dependency consumed by the next stage.

### 1. Bit-width sweep

```bash
python experiments/01-bitsweep/run_bitsweep.py
```

After reviewing the downloaded bundle, record the chosen bit configuration on
the server:

```bash
python experiments/01-bitsweep/narrate_bitsweep.py \
  --select_config 7+7 \
  --rationale "reviewed rationale"
```

Raw daily Collapse and raw daily Unique counts scale with the codebook and must
not be compared across bit configurations. Use the vocabulary-invariant
evidence instead: DA / daily RankIC / MAPE with their `min_window_*` floors, the
`median_daily_*_alignment` and `codebook_balance` fields that compare a
prediction against its same-day target, and `H(target) - CE` in bits. All of
these are already in `combined_epoch_summary.json`.

The full decision argument, with eight figures, is regenerated by:

```bash
python experiments/01-bitsweep/report_bitsweep.py
```

### 2. Tokenizer architecture

```bash
python experiments/02-tokenizer-tuning/run_tokenizer_sweep.py
```

Bits are fixed here, so quality metrics are directly comparable; behaviour is
still read through the normalized alignment fields because different encoder
capacities fill the fixed codebook differently. The runner exports per-layer
coarse/fine/joint code utilization, and the analyzer writes a staged screen
(quality floors, then normalized behaviour, then tokenizer sufficiency).

After review:

```bash
python experiments/02-tokenizer-tuning/analyze_tokenizer_epochwise.py \
  --select_config 64x192 \
  --rationale "reviewed rationale"
```

### 3. Controlled GPT capacity

```bash
python experiments/03-gpt-scaling/run_gpt_capacity.py
```

The formal run writes `selection_proposal.json`. After review, promote the
proposal:

```bash
python experiments/03-gpt-scaling/analyze_gpt_capacity.py \
  --record_selection \
  --rationale "reviewed rationale"
```

### 4. Loss, optimizer, and HPO

```bash
python experiments/04/a-loss-ablation/sweep_loss.py
```

After reviewing Exp 04-A:

```bash
python experiments/04/a-loss-ablation/sweep_loss.py \
  --analyze_only --record_selection \
  --select_arm ce \
  --selection_rationale "reviewed rationale"
```

Then run and review Exp 04-B in the same way:

```bash
python experiments/04/b-optimizer-ablation/sweep_optimizer.py
python experiments/04/b-optimizer-ablation/sweep_optimizer.py \
  --analyze_only --record_selection \
  --select_arm muon \
  --selection_rationale "reviewed rationale"
```

Only then start HPO:

```bash
python experiments/04/c-hpo/sweep_hpo.py
```

The holdout remains sealed until the explicit HPO holdout command.

## Smoke tests

Each entry point supports `--smoke`. Exp 01 can smoke independently; later
smokes require the preceding reviewed selections, or an explicit upstream
artifact such as `--bits`/`--tokenizer`.

```bash
python experiments/01-bitsweep/run_bitsweep.py --smoke
python experiments/02-tokenizer-tuning/run_tokenizer_sweep.py --smoke --bits 7+7
```

tar --exclude=.git --exclude=.venv --exclude=server_runs \
